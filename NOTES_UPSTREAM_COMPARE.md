## 4. What upstream has that we lack

- **Loader robustness** (f24c92e): `typeof(Auga).Assembly`, `ShouldLog`, and `Panel_Create` without the sleep. See §1. These are small, clean ports and **worth taking**.
- **Averia font fallbacks** on the Source Sans TMP fonts, so mod glyphs such as EpicLoot's bullet render.
- **Compatibility with mods that embed the old AugaAPI shim**: APIManager plus the nested-types patch, tested with EAQS and EpicLoot. This is our biggest functional gap for existing mods (STRETCH.md).
- **Full Auga rebuilds of main-menu screens:** settings with Auga widgets, start game/world/server rows, world modifiers, character select/new with the portrait cache and 5-per-frame budget, Manage Saves, changelog, agreement, credits. Plus the `AugaPanelRestyler` generic tool with RestyleOptions and scroll sensitivity 600 everywhere (5925726).
- **TMP migration of every prefab.** It removes the whole class of legacy-Text bugs we patch one by one.
- **Build menu rebuild:** AugaTextInput search, Q/E tab bar, repair row, dimmed unbuildable pieces. Centre messages shown while building.
- **Achievements tab in the compendium.**
- **Map:** ping selector wired, so icon clicks no longer throw. We should re-test that path. Filter greys the pin icons.
- **HUD:** status-effect Standard items, single-line names, map-aligned list. Message log behind the player panels.
- **Inventory:** single tab click sound. His split-dialog ordering matches our inventory-9.
- **Crafting:** one-of-many recipes and per-quality counts in the requirement wires. Compare with ours.
- **Loading-screen art** for the newer biomes. A rebuilt bundle with those sprites (126 MB).
- **Tooling:** in-repo AugaAutoStart smoke test (EpicLoot, Magic and Enchanting steps), setup-references.ps1, BUILDING.md.

## 5. Building upstream (scratch only, nothing deployed)

- **`setup-references.ps1`**: publicizing into `References\Valheim` succeeded. The APIManager step clones github.com/blaxxun-boop/APIManager (network access needed) into `%TEMP%\AugaAPIManagerBuild` and applies the patch. It then aborted: vswhere could not find VS2022 MSBuild, and this machine's Build Tools also lack the .NET Framework 4.8 targeting pack (MSB3644) and SDK-style support in msbuild.exe (MSB4236).
- **Workaround.** APIManager was built with a scratch SDK-style wrapper (`scratchpad\apim-sdk`, net48 via Microsoft.NETFramework.ReferenceAssemblies) and gave APIManager.dll (23 KB).
- **`dotnet build Auga/Auga.csproj -c Release -p:DeployToValheim=false -p:ValheimDir=D:\SteamLibrary\steamapps\common\Valheim -p:BepInExDir=<same>`**:
  - C# compile **succeeded with 0 warnings** for UiLibShim, AugaUnityLib and Auga.
  - Only the **ILRepack** post-step failed (MSB4062: the task needs `Microsoft.Build.Utilities.v4.0`, a .NET Framework msbuild). BUILDING.md warns about this.
  - The unmerged output was copied to `scratchpad\up-build\Auga-Release`: Auga.dll **126.9 MB** (the bundle is embedded), Unity.Auga.dll 120 KB, APIManager.dll.
  - It would work in game only if APIManager.dll is also loaded, since it was not merged.
- **`-c API`**: `AugaAPI.dll` compiled. Only ILRepack failed again.
